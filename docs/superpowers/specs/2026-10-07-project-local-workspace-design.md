# 项目本地工作区设计

## 目标

将每个浏览器中创建的 Multica 项目映射为 Mac 上一个独立工作目录。该项目里的所有聊天，不论选择哪一个本地智能体，都以该目录作为可按需搜索、读取和编辑的工作目录。

同步根目录保持为 `/Users/mac/Documents/multica`。每个项目的目录与项目名称同步；会话目录仍用于保存聊天记录，但智能体执行时使用项目根目录，而不是某一条聊天的目录。

## 用户规则

- 创建项目时，自动创建并绑定 `Documents/multica/<项目名>`。
- 项目内创建的聊天自动继承该项目的本地目录；切换智能体不会改变目录。
- 将聊天拖到另一个项目后，后续任务改在目标项目目录执行。
- 未归类聊天不绑定任何项目目录，也不会取得项目文件访问。
- 改项目名称时，同步器重命名项目目录；删除项目时，同步器删除该项目目录和其中的聊天导出目录。
- 同一项目内的聊天仍保持各自独立的聊天历史；共享的是项目文件，而不是把彼此的消息塞入上下文。

## 架构

复用 Multica 已有的 `project_resource` 的 `local_directory` 类型，而不新增提示词拼接或文件上传协议。

1. 浏览器创建项目后，服务端为当前 Mac 的本地 daemon 创建一条 `local_directory` 资源：
   `{ local_path, daemon_id, label, execution_mode: "in_place" }`。
2. 本机同步服务在创建或改名项目目录后，确保其对应资源使用同一个绝对路径。
3. daemon 领取项目内聊天任务时，已有的项目资源解析链把该路径作为智能体的工作目录。
4. 智能体按其工具调用搜索、列出和读取文件；系统不枚举或注入整个大目录，因此上下文大小与文件夹大小无直接关系。

`in_place` 是本期固定模式：智能体直接在 Finder 中看到的项目目录工作，最符合本地同步的预期。Git worktree、任意目录选择、多个 daemon 的路径映射不纳入本期。

## 边界与失败处理

- 只有与当前 Mac daemon 匹配的资源会被自动维护；手机/其他电脑只使用该资源，不创建本地路径。
- daemon 未连接时，项目与聊天可正常创建；目录资源在下次同步时补齐，聊天任务在本机 daemon 可用后才可读取文件。
- 目录名称会沿用同步器已有的文件名清洗与稳定 ID 策略，避免重名或非法路径导致覆盖。
- 项目删除只删除同步根目录内、且 metadata 中项目 ID 匹配的目录，绝不删除任意用户路径。
- 如果资源写入失败，浏览器聊天功能不受影响；UI 显示“本地工作区未连接”，同步器下次重试。

## 测试

- 新建项目会创建与当前 daemon 绑定的 `local_directory` 资源，路径位于同步根目录。
- 项目内聊天任务的领取载荷包含该资源；未归类聊天不包含。
- 重新命名项目会让本地目录和资源路径收敛到新路径。
- 移动聊天到另一项目后，后续任务只携带目标项目资源。
- 删除项目只清理其受 metadata 保护的目录与资源，不会越出同步根目录。
- 对大目录的行为测试只断言按需工具访问，不读取或序列化整个目录。
