# 审核后的自动修复与复审

## 目标
审核智能体发现明确可修复的问题后，系统自动把问题交给任务的执行智能体修改；修改完成后由审核智能体复审。用户通过收件箱了解进度、失败和需要决策的问题。

## 流程
1. 审核结果使用结构化结论：通过、需要修改、需要用户决策或审核失败；需要修改时包含具体问题、证据和受影响任务。
2. 对需要修改的结论，系统查找对应任务的执行智能体，验证它的工作区、运行环境及权限，随后创建修复运行，附上审核意见。无法确定合适执行者时通知用户，不猜测或跨任务派发。
3. 修复运行要求修改代码、运行适当测试并报告结果。成功后派发给原审核智能体复审；无结果、失败或运行环境不可用时保留可见错误并通知用户。
4. 以同一任务和审核轮次为单位记录状态和派发标识，防止重复派发；限制自动修复与复审最多三轮，达到上限后停止并说明阻塞原因。
5. 收件箱区分审核中、修复中、复审通过、需要决策和执行失败；任务状态在真实进入相应阶段后更新，不把代码修改或审核通过当作部署完成。
6. 跨任务日报只汇报，不根据自由文本自动派发修复；自动修复以单任务的结构化结果为准。合并、部署及其他需要额外授权的动作不由此流程自动执行。

## 验证
使用隔离数据库及测试替身覆盖正常闭环、无执行者、审核或修复失败、重复事件、并发、重试上限和权限校验；检查收件箱与任务状态。真实智能体端到端验证单独取得明确授权；部署前备份并确认原正式数据库及外网地址。
