# 浏览器 Chat 本地同步设计

## 目标

用户只在浏览器使用 Multica，也能将项目和直接 Chat 的完整记录同步到本机。同步根目录固定由用户授权为 `/Users/mac/Documents/multica`，由独立的 `multica-sync` 后台服务负责写入，浏览器永远不直接访问文件系统。

## 用户体验

浏览器内创建项目、在项目中创建或移动对话、修改标题、发送消息、删除对话或项目后，本机同步服务自动处理对应目录与文件，无需打开 Multica Desktop。

```text
/Users/mac/Documents/multica/
  项目名--project_abc123/
    对话首句--chat_def456/
      conversation.md
      metadata.json
```

项目与对话目录都带稳定短 ID，标题仅供阅读。重名不会覆盖；路径分隔符、控制字符与连续空格都会被安全转换。

删除对话会删除对应的本地对话目录。删除项目不会删除对话：服务端会把子对话的 `project_id` 清空；下一轮同步把每个目录移动到根目录下的 `未归类--unassigned/`，并清理原来的空项目目录。

## 服务端

复用现有 project、chat_session、chat_message API 与 `project_id` 关联。第一期同步器轮询当前用户可见的项目、Chat 和完整消息快照，因此不需要等待服务端新增事件表，也能在离线后收敛到正确状态；远端不再返回的 Chat 会被安全清理。后续可将轮询优化为用户私有的顺序事件流，但不改变本地目录或元数据格式。

## 本机 multica-sync

`multica sync once --root /Users/mac/Documents/multica` 可立即执行一次同步；`multica sync start --root /Users/mac/Documents/multica` 作为本机后台轮询服务运行。它复用当前 CLI 的登录与工作区凭据，并将所有目标路径限制在指定的根目录内。

对每个非删除事件，同步服务获取会话标题、项目归属与完整消息，原子重写：

- `conversation.md`：按时间顺序记录用户和助手可见消息；附件和非文本消息使用简短占位，不记录模型推理或工具内部事件。
- `metadata.json`：project ID、chat session ID；它是本地删除和移动的唯一授权标记。

改名时先校验 metadata 的 ID，再原子重命名；删除时仅删除 metadata 中 ID 与目标完全匹配的目录；无法验证、越出根目录或删除失败只记录错误并保留文件。

## 项目内对话

第一期复用 `chat_session.project_id`，不新增项目/会话关联表。项目说明、Skill 和关联资源是共享背景；每个 Chat 的消息历史和底层模型会话仍保持独立，避免单一长上下文膨胀。

## 安全与故障策略

- 第一版使用现有 CLI profile 的登录与工作区凭据；配对令牌和单设备吊销属于后续增强。
- 未配置同步根目录时服务不写文件。
- 网络、鉴权、文件系统错误不影响浏览器内项目或 Chat 的正常创建、改名、发送和删除。
- 同步失败可在下一次轮询重试；每一轮都按当前浏览器快照收敛。

## 测试

覆盖首次同步、项目移动、首句标题、手动改名、文件名清洗、完整 Markdown 渲染、离线补齐、元数据验证删除、根目录逃逸和未配置根目录时拒绝写入。事件排序、断点续传和设备令牌将在事件流版本中覆盖。
